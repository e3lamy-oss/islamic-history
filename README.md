# مسارات التاريخ الإسلامي

لوحة تفاعلية للتاريخ الإسلامي من عام الجماعة (41 هـ): محور زمني رأسي بالهجري والميلادي، ومسارات متوازية للدول المتعاصرة، والعلماء، والأحداث الفاصلة.

## البنية

| الطبقة | التقنية | السبب |
|---|---|---|
| الواجهة | HTML/CSS/JS بلا إطار عمل (`site/`) | سريعة، بلا اعتماديات تُخترق، تُخدَم ملفات ثابتة |
| البيانات التاريخية | ملف ثابت `site/data.js` داخل المستودع | قراءة فقط بطبيعتها: لا يوجد أي مسار عام يستعلم قاعدة بيانات، فلا مجال لحقن SQL في المحتوى التاريخي. كل تعديل يمر بطلب دمج في Git، فيكون لكل تغيير سجل ومراجعة |
| الاستضافة | Cloudflare Workers مع الملفات الثابتة (Static Assets) | HTTPS إلزامي، حماية DDoS، جدار حماية WAF، شبكة توزيع عالمية |
| واجهة الملاحظات | `functions/api/feedback.js` يستدعيه `worker/index.js` | تحقق من المصدر، Turnstile، تحديد معدل، استعلامات مُعدّة |
| قاعدة الملاحظات | Cloudflare D1 (`db/schema.sql`) | للملاحظات وسجل التدقيق فقط |
| لوحة الإدارة | `site/admin/` + `functions/admin/` خلف Cloudflare Access | تسجيل دخول بتحقق ثنائي إلزامي على الحافة، ثم تحقق ثانٍ من توقيع الرمز داخل الكود |
| النسخ الاحتياطي | GitHub Actions يومياً (`.github/workflows/backup.yml`) | تصدير D1 مشفّر بـ age إلى R2، إضافة إلى الاسترجاع الزمني المدمج في D1 |

## مطابقة متطلبات الأمان

- **قاعدة بيانات للقراءة فقط:** المحتوى التاريخي ملفات ثابتة. قاعدة D1 لا تحوي إلا الملاحظات، وكل استعلام فيها مُعدّ مسبقاً (`bind`).
- **فصل لوحة الإدارة + 2FA:** Cloudflare Access يفرض تسجيل الدخول والتحقق الثنائي قبل وصول الطلب، والوسيط `functions/admin/_middleware.js` يتحقق من توقيع الرمز والجمهور والبريد المسموح. يمكن لاحقاً نقل اللوحة إلى نطاق فرعي مستقل (`admin.example.org`) كمشروع منفصل.
- **الأسرار:** `TURNSTILE_SECRET` و`IP_SALT` تُضبط في إعدادات Cloudflare ولا تظهر في الكود ولا في المتصفح. مفتاح Turnstile العام (site key) فقط يظهر في الصفحة، وهذا مقصود.
- **DDoS والبوتات:** حماية Cloudflare المدمجة في كل الخطط، مع Bot Fight Mode وقواعد WAF. خطة Enterprise ليست ضرورية في البداية.
- **تحديد المعدل:** 5 ملاحظات في الساعة لكل عنوان (يُحفظ كبصمة مملّحة، لا كعنوان صريح)، مع Turnstile وحقل فخ. يُنصح بإضافة قاعدة Rate Limiting في WAF على `/api/*` كطبقة ثانية.
- **HTTPS والهيدرز:** `site/_headers` يفرض HSTS وCSP صارمة (بلا سكربتات مضمّنة ولا `unsafe-inline`) ويمنع التضمين في إطارات. لا توجد ترويسات CORS، فالواجهة لا تقبل إلا طلبات من الموقع نفسه، مع فحص `Origin` ضد CSRF.
- **XSS:** كل نص يُعرض يمر بالتهريب (`esc`) أو `textContent`.

## خطوات التشغيل على Cloudflare

1. مشروع Worker باسم `islamic-history` مرتبط بهذا المستودع، وأمر النشر `npx wrangler deploy`. ربط D1 والمتغيرات معرَّف في `wrangler.toml`، والأسرار وحدها تُضبط من لوحة Cloudflare.
2. `npx wrangler d1 create islamic-history-feedback` ثم ضع المعرّف في `wrangler.toml`، ثم `npx wrangler d1 execute islamic-history-feedback --remote --file=db/schema.sql`.
3. Turnstile: المفتاح العام موضوع في `site/index.html`، والسري في السر `TURNSTILE_SECRET`.
4. أضف `IP_SALT` (نص عشوائي طويل) كسر.
5. في Zero Trust أنشئ تطبيق Access للمسار `/admin/*` مع سياسة تفرض التحقق الثنائي، وضع `ACCESS_TEAM` و`ACCESS_AUD` و`ADMIN_EMAILS`.
6. لنسخ الاحتياط: أنشئ حاوية R2 `islamic-history-backups` ومفتاح age، وأضف أسرار GitHub المذكورة في ملف العمل.

## التشغيل محلياً

افتح `site/index.html` مباشرة في المتصفح لتصفح اللوحة. لتجربة واجهة الملاحظات: `npx wrangler dev`.

## منهج البيانات

- لكل سجل سنتاه الهجرية والميلادية مدخلتان صراحةً، ومراجعه، وحالته (`draft` مسودة، `review` تحتاج تدقيقاً إضافياً). الأرقام الميلادية على المحور تقريبية للتوجيه فقط.
- العلامة `~` تعني أن التاريخ تقريبي أو مختلف فيه.
- الملاحظات المقبولة في لوحة الإدارة تُطبَّق بتعديل `site/data.js` عبر طلب دمج، فيبقى لكل تصحيح أثر ومراجِع.
